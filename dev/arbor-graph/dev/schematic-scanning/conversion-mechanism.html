Schematic → 3D: how the conversion works

Arbor building scanner · architectural floor-plan PDF → browser-rendered 3D model

The schematic is never "converted to HTML." index.html is a fixed Three.js renderer. The real work is parsing each drawing into JSON that the page loads. Source drawing → JSON → 3D in the browser.

The whole pipeline

The two extraction routes

A · VISION

Read the picture

extract.py
  1. Rasterise. PyMuPDF crops the title block (right ~15%) and renders the page to a 4096px PNG — big enough that ~10px room labels survive o3's 2048px tiling.
  2. Ask o3 vision. PNG is base64'd and sent with a strict prompt: return ONLY JSON — every enclosed space with id, label, type, normalised bounds, neighbours, plus lifts/stairs as cores.
  3. Parse & fan out. Strip ``` fences, save JSON. One "Level 2–5" sheet is deep-copied and re-IDed into 4 identical floors.

→ floors/*.json  (semantic: what each room is)

B · VECTOR

Read the geometry

vector_extract.py
  1. Native lines. Reads the PDF's actual vector strokes (get_drawings), keeps only wall-weight ones (width ≥ 0.5); thin clutter dropped.
  2. Find the plan. Segment midpoints fill a 48×48 occupancy grid; the largest connected blob (BFS) is the real plan — legend/section cropped away.
  3. Normalise. Uniform scale to 0–1, aspect preserved, y-flipped. Same recipe every floor, so identical footprints stack.
  4. Split walls. A Shapely concave hull → smooth outer envelope; interior midpoints → inner partitions.

→ walls.json  (geometric: where every wall is)

The HTML

index.html is a static Three.js page. On load it runs three fetch()es — graph.json, walls.json, building.json — then extrudes the normalised 0–1 geometry into 3D: floor slabs, inner partitions, a glass outer envelope, and glowing lift/stair cores, with hover readouts and per-floor toggles. Because all the geometry math was done upstream, the renderer just does coord × SCALE. Serve with python -m http.server 8181 and the same HTML visualises any building whose JSON you drop beside it.

One line: the schematic isn't converted to HTML — it's parsed (by vision and/or vector analysis) into a normalised room + wall + portal graph in JSON, and a fixed Three.js HTML page renders that JSON as a 3D model.
